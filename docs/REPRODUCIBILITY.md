# Reproducibility guide

## Execution paths

The public entry point is `reproduce.py`; it uses paths relative to its own
location and accepts an explicit output directory. Generated files are kept
outside the reference and source directories.

| Command | Work performed |
|---|---|
| `verify` | Unit tests, all-stage independent checks and regeneration of paper inputs |
| `smoke` | Unit tests plus a ten-mission, single-budget run and its consistency checks |
| `run` | Complete numerical experiments, comparison with supplied results and table export |
| `all` | Complete `run` pipeline, table export, and all figure builds |
| `export` | CSV/LaTeX export from supplied or explicitly selected results |
| `figures` | Four figure builds from supplied or explicitly selected results |
| `inputs` | Materialize independent main design/calibration samples |
| `integrity` | Validate the release's file hashes |

`--results PATH` selects inputs for `verify`, `export`, or `figures`.
`--output PATH` selects the generated output location. The `--episodes` option
applies only to the smoke test; the full experiment uses 500 missions.
`--no-png` permits PDF builds without Poppler.

A smoke run uses different random call shapes from a 500-mission run. Its purpose
is checking execution and internal consistency. The full mode is the reference
for the paper's numerical results.

## Reference records and a fresh run

`reference/results/` retains the supplied scientific records. The full pipeline
regenerates its own design and calibration samples, starting from the documented
seeds. It also regenerates the fresh deployment shocks. No archived state
trajectory is used as an input to a new control simulation.

`src/certified_benchmark.py` produces the main study and supplementary diagnostics.
`src/compare_certificates.py` performs the controlled certificate comparison.
The export layer has no dependency on external project directories.

The independent main design/calibration arrays are also supplied in
`reference/inputs/` for direct inspection. These arrays are generated by the
same documented routines and have their own integrity hashes.

## Comparison policy

All 84 numerical results files are checked. The CSV comparator checks schemas
and row order. Integer columns must match exactly. Floating-point columns use
`abs(a-b) <= 1e-8 + 1e-9*abs(b)`, with matching missing-value positions.
The exogenous NPZ arrays must match exactly. JSON configuration/validation
records are also compared; Python/library version fields are recorded separately.

Only `qp_ms` and `mean_qp_ms` are excluded from the CSV comparisons. These are
measured wall-clock quantities. Their archived and new measurements remain
available for inspection. Gzip headers and PDF metadata can contain execution
timestamps, so comparisons use their scientific contents.

`validation/full_rerun_comparison.json` records the measured discrepancies of
the delivered verification run. `validation/end_to_end_report.json` records
execution of the public full command. The run's environment is recorded in
`validation/environment.json`.

The reported tolerances are regression thresholds. They should be reviewed when
porting to a different numerical stack. Large changes or different discrete
outcomes cause a nonzero process exit status and remain visible in the report.

NumPy's random-stream compatibility conditions include the call sequence and
array shapes, in addition to the seed and numerical environment. See the official
[NumPy compatibility policy](https://numpy.org/doc/2.3/reference/random/compatibility.html).
The SLSQP stopping parameter controls several optimality and feasibility checks;
its precise meaning is documented in the
[SciPy 1.17.0 solver reference](https://docs.scipy.org/doc/scipy-1.17.0/reference/optimize.minimize-slsqp.html).

## Independent validation

The unit suite checks the nonsymmetric ellipsoid support and finite-sum tube
support. It verifies the condensed dynamics, objective and analytic gradient.
It also checks Riccati consistency and feasibility behavior. Exact-binomial
endpoint/tail tests include enumerated finite-sample coverage checks. A forced
unattainability test verifies permanent certificate stopping with an unchanged
unspent risk balance.

The all-stage verifier checks all 450,000 stored executed stages. It reconstructs
the fresh shock selected by context and the successor state. Costs and physical
flags are recomputed. Every episode aggregation and sequential risk-ledger
identity is reconciled. Selected sets are checked against the observed residual,
and certified charges are matched to the exact operational table.

For certified steps the verifier checks the first-step robust implication and
independently reconstructs the tightened next-state bounds. Stored accepted QP
residuals are checked against the hard-constraint tolerance. All ten calibration
configurations are regenerated, including integer miss counts and component
bounds. The paired-query checks preserve failed comparisons and their denominators.

These checks establish computational consistency for the stored and regenerated
experiments. The mathematical coverage statements use the conditional-law and
independence assumptions stated in the paper. A successful finite collection of
missions is an empirical observation about those missions.

## Rendering and source handling

The scientific experiment routines preserve the supplied implementation.
`validation/source_integrity.json` records their source hashes and an executable
syntax-tree comparison. The final manuscript is distributed only as `paper/manuscript.pdf`; its LaTeX source is intentionally omitted. Figure 4 has a layout-only axis-label offset to prevent overlap.

The numerical paper inputs are generated from the same results used for the
reported tables. Regenerating them from the supplied results yields byte-identical
copies of all 17 files in `paper/data/`. Standalone figure wrappers preserve the
IEEEtran font and text dimensions. The manuscript PDF is a fixed publication artifact and is not rebuilt by the reproducibility commands.

## Dependency installation check

The complete local runs used installed package versions that match `requirements.lock`.
A separate attempt to download dependencies into a fresh environment was blocked
by DNS/network restrictions. This setup limitation is recorded in
`validation/setup_checks.json`; the numerical reruns and rendering checks completed
in the recorded environment.

## GitHub workflow and maintenance

The included workflow runs integrity checking and verification, followed by a
smoke simulation and figure build. The manually selected full job runs all
500-mission experiments. Both jobs retain their generated output as workflow
artifacts. The workflow definition is included; remote GitHub execution occurs
when the repository owner enables and runs it after publication.

The integrity manifest freezes the delivered release. After intentional edits,
review the new results and refresh the manifest with:

```bash
python scripts/update_manifest.py
```

The manifest excludes generated build directories and Python bytecode. New
scientific results should be reviewed before replacing the reference records.
